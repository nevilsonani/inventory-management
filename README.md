# SasthaSoft Inventory

An inventory management app for a distributor with three godowns. Sales,
purchases, stock, godowns and reports are connected: every order moves real
stock, and every movement is recorded.

Built with **Next.js 16** (App Router), **React 19** and **Tailwind CSS v4**.
It ships with six months of sample data and needs no login or backend.

## Modules

| Module | What you can do |
| --- | --- |
| **Dashboard** | Revenue, inventory value, receivables and stock alerts; sales vs purchases chart; low stock alerts with one-click reorder; a "needs attention" list; recent activity; top sellers |
| **Sales** | Sales orders and invoices with customer, amount and status (Pending, Dispatched, Overdue, Paid, Cancelled). Filter by status, customer and godown, search, export CSV. Dispatch or mark paid from the row or the order panel |
| **Purchases** | Purchase orders with supplier, godown and status (Pending, Delayed, Received, Cancelled). Receive from the row or the order panel |
| **Stock** | Every item with quantity per godown, minimum level, status and value. A full stock history (ledger) with filters. Each item has a page with a 90-day stock chart, committed and incoming quantities, and its movements with running balance |
| **Godowns** | Units, value and space used per godown; transfers between godowns |
| **Customers / Suppliers** | Billed and outstanding amounts per customer; spend, average lead time and on-time rate per supplier. Rows open that party's orders |
| **Reports** | Stock, sales and purchase reports with a date range, charts, tables, CSV export and print |

Also: a command menu (**Ctrl/⌘ K**) to search items, orders and actions, a
light/dark theme toggle, and a layout that works on phones.

## How the workflow connects

- **Receiving a purchase order adds stock** to its godown.
- **Dispatching a sales order removes stock** and raises the invoice. Dispatch
  is blocked when a godown is short, and the form shows how many are available.
  The order can still be saved as pending.
- **Low stock shows on the Dashboard** (and in the sidebar badge). "Reorder"
  opens a purchase order filled in with the preferred supplier, the godown
  holding the least stock and a suggested quantity.
- **Transfers and stock counts** move stock between godowns or correct it,
  each with a ledger entry.
- Overdue invoices and delayed deliveries are worked out from due and
  expected dates, and surface on the Dashboard.

### Try it in two minutes

1. On the Dashboard, click **Reorder** next to *1TB NVMe SSD* and place the order.
2. Open **Purchases**, click **Receive** on that order. Stock goes up and the alert clears.
3. Click **New sale**, pick a customer and an item, then **Create & dispatch**. Stock goes down.
4. Open the item from **Stock** to see both movements in its history.

## How it is built

```
src/
  app/            Routes. Each page renders one feature view.
  features/       One folder per module (dashboard, sales, purchases, stock,
                  godowns, contacts, reports) plus shared order parts.
  components/
    ui/           Design system: button, card, dialog, table, badge, fields…
    charts/       Small hand-written charts (columns, step line, bar list)
    layout/       App shell, sidebar, command menu, theme toggle
  lib/
    types.ts      Domain model
    domain.ts     Business rules as pure functions (state in, state or error out)
    selectors.ts  Derived values: stock status, totals, overdue, time series
    seed.ts       Sample data, created by replaying domain.ts
    store.ts      Browser store: memory + localStorage, synced across tabs
```

Key decisions:

- **Rules live in one place.** `lib/domain.ts` holds every rule (dispatch,
  receive, transfer, adjust) as a pure function that returns the next state or
  a readable error. The UI calls these and shows the result. The sample data
  is generated by running the same functions, so it always follows the rules.
- **No backend, by design.** Data is stored in the browser (localStorage), so
  each visitor gets their own copy and changes survive a refresh. The sidebar's
  reset icon restores the sample data. Swapping `lib/store.ts` for API calls
  would leave the UI and the rules unchanged.
- **Filters live in the URL** (`/sales?status=overdue`), so views can be linked
  to from the Dashboard and survive a refresh.
- **Accessible by default.** Dialogs use the native `<dialog>` element (focus
  trap, Escape, inert background); statuses always have a text label, not
  colour alone; charts show their values as text, and column charts include a
  hidden data table for screen readers.
- **Dark mode via tokens.** The colour scales flip under `[data-theme="dark"]`
  (see `app/globals.css`), so components need no `dark:` variants. An inline
  script applies the saved theme before first paint.
- **Small dependency list:** `lucide-react` (icons), `sonner` (toasts),
  `clsx` + `tailwind-merge`. Charts are hand-written.

## Run locally

Requires Node.js 20.9 or newer.

```bash
npm install
npm run dev        # http://localhost:3000
npm run check      # type check, lint and production build
```
